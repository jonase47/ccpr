The PostToolUse gate in hooks/agent-monitor.py declares HANDOVER_WRITE_TOOLS = {"Write", "Edit", "MultiEdit", "NotebookEdit"}, but only "Edit" is pinned by a test. Verified 18.08.2026 by mutation on a scratch copy: reducing the set to {"Edit"} alone leaves all 429 tests green.

Consequence: a HANDOVER rewritten via Write -- the full-rewrite case, which is what a compaction pass actually does -- would silently stop being size-checked, and nothing would report it. Three compaction passes in the session that produced this work item were exactly that shape.

Two smaller gaps in the same function, both mutation survivors from the same run: the basename comparison can be mutated to a substring match (making docs/HANDOVER.md.bak count as a HANDOVER write) without any test failing; and the dedup key can drop source_event without failing, because no test mixes a SessionStart and a PostToolUse warning inside one session -- so the documented (session, source_event, level) contract is only two-thirds pinned.

Fix: one test per declared tool, a pin on exact-basename matching, and a test that warns once per event within a single session. None of this changes behaviour; it defends behaviour that already exists.
