commands/release-baseline.md section 4 ("Reset HANDOVER.md") creates a fresh HANDOVER from the template after a release cut. With the append-only inbox introduced in WI-0002, an untriaged entry is destroyed by that reset without any warning -- the one place in the shipped surface where a captured finding can be lost silently, which is precisely the failure the inbox exists to prevent.

/cleanup already forbids archiving the inbox section while it holds untriaged entries. The same guard is missing here.

Fix shape: before resetting, check the inbox; if it holds entries, either require them to be triaged first (consistent with /cleanup) or carry them over into the fresh file verbatim. Carrying over is likely the better default at a release cut, since the reset is not optional at that point.
