Detection gaps left open when the artifact gate (WI-0004) was built, all recorded rather than fixed in that round so the repair stays visible.

(1) "Authorization: Bearer <token>" is not covered. The generic 40-character length rule was removed because it produced all 18 false positives (Markdown table separators, long snake_case test names), and was replaced with shapes a machine-generated credential actually has -- hex >= 32, JWT, padded base64, vendor prefixes. A bearer header carrying a token that fits none of those shapes now passes. This is new detection, not a repair of the removal.

(2) Four mutations survived the review's hunt over discipline_gate.sh: the hex-32 boundary, the email pattern's terminal anchor, the /home/ arm of the personal-path check, and gate_scan_file's return contract. These are exactly the tests that would catch the next narrowing of this kind -- which is the class of defect that produced this work item's two blockers (a placeholder exemption that swallowed real passwords, and a keyword-value backstop that missed JSON).

(3) The self-exemption for the pattern-source file suppresses nothing in the artifact profile today: scanning an unexempted copy yields 0 findings. It is correct preventive design, but it has never been seen red, so nothing proves it works when it starts to matter.
