93 files under commands/ carry a Handover-Epilogue bullet reading "- Open points", instructing the command to record open points in docs/HANDOVER.md. WI-0002 introduced a HANDOVER section literally named "## Open Points (append-only inbox)" with a strict, machine-readable entry format.

The collision: an agent following one of those 93 epilogue bullets will plausibly write free prose into the inbox section, which the /cleanup triage step cannot parse and which therefore neither counts toward the ceiling nor gets triaged. The section then silently accumulates unstructured text while reporting zero entries.

Rewording 93 shipped skill prompts is a change to the shipped skill surface and needs an ADR plus a migration path under the Constitution ("No breaking skill-interface changes without ADR + migration") -- which is why it is not part of WI-0002.

Options to weigh: (a) reword the epilogue bullets to name the target explicitly (decisions table vs inbox), (b) make the /cleanup triage tolerant of unstructured lines inside the section and report them as "unparseable, needs reshaping", (c) rename the inbox section so it no longer collides -- which would cost the p5-polish resolution that motivated the current name.
