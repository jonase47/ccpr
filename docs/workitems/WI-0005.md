Check (n) in memory-lint.sh ships at "warn" because its Markdown link extraction has two known gaps, both reproduced on 18.08.2026.

(1) Fenced and inline code examples are false positives: an index documenting its own link syntax in a fenced markdown block, or inline in backticks, produces findings for links that are illustrations rather than entries. Fixing it needs fenced-block state in the awk. The shipped templates/MEMORY_INDEX_TEMPLATE.md contains no example links, so nothing CCPR ships trips this today -- latent, not shipped-broken.

(2) Reference-style links are not checked at all: a collapsed reference plus its definition line passes silently. That is the same defect class the check exists for, one syntax further.

Completion criterion: with both closed, flip MEMORY_INDEX_LINK_SEVERITY from "warn" to "err" (one line, top of memory-lint.sh) so the check matches check (f), which already errors on a cross-reference to a non-existent file. Per ADR-0001 that promotion is the SemVer-relevant step, because it rejects previously-accepted content -- it must be a deliberate, visible change, not a silent one.
