cmd_promote in scripts/memory-sync.sh never checks its destination path against the configured deny-list, and that path is written into a commit message that is then pushed.

Severity is higher than anything found in artifact-gate, for one reason: this path publishes irreversibly. The artifact sweep is a local check whose failure means a leak stays in a working tree; a promote pushes to a shared repository, where a tenant name in a commit message survives deletion of the file and is visible to everyone with read access. Rewriting shared history to remove it is the expensive kind of remedy.

Found 18.08.2026 while reviewing WI-0004. It is adjacent to the two gaps fixed in that work item (memory-sync ignoring the unusable-entry signal, and never reporting an entirely unconfigured deny-list) but was deliberately left out of that round so the fix stays visible rather than smuggled into a refactor.

Fix shape: run the destination path through the same deny-list check the content already gets, before anything is staged or committed, and refuse rather than warn -- a push cannot be taken back. Worth checking in the same pass whether any other string that reaches a commit message or a branch name is unchecked.

## Comments
- Implemented and reviewed twice. The first review found the check bypassable: a directory destination made cp append the source basename, so the checked string and the published string differed -- reproduced against a local bare remote with the name reaching the pushed tree. Closed by rejecting directory destinations as the usage error the documented contract always described, plus three narrower bypasses (ASCII-only folding, NFD/NFC, missing -- on git add). Verified independently by inspecting the bare repo, not the exit code: after a refusal, 0 refs, 0 commits, no clone created. 596 tests green. Residuals in WI-0017; output masking in WI-0016.
