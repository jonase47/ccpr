templates/MEMORY_SCHEMA.md declares itself applicable to Tier-2 topic files (line 4: "and Tier-2 topic files (docs/memory/{agent}/{topic}.md)") and leaves the topic slug free (line 28), but it never defines a type value suitable for them. memory-lint.sh check (c) enforces the Tier-1 content enum {feedback, project, reference, user} on every file under docs/memory/ except MEMORY.md and instincts.md -- including persona topic files.

Measured 18.08.2026 across the three Tier-2 topic files that exist in this repo: three personas, two different invented values. code-reviewer/patterns.md carries "type: project" (passes by coincidence, since a persona pattern file is not a project fact); senior-developer/patterns.md and tech-writer/handover-template.md both carry "type: patterns" and both fail the lint. Two agents independently reached for the same value the schema does not offer -- that is a gap in the schema, not two typos.

This is the same failure class as the status-enum drift recorded as a precondition in ADR-0009: where the schema does not cover a case, agents invent a value and the register drifts silently.

Options to weigh: (a) extend the enum with a Tier-2 content type and say so in the schema, (b) exempt Tier-2 topic files from the content-type check and validate them against their own field set, (c) require an explicit tier or scope field so the lint can pick the right enum per file. Whichever is chosen, fix the three existing files in the same pass so the register stops disagreeing with itself.
