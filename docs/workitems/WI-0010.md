parse_handover_cap in hooks/agent-monitor.py was deliberately given several tolerances, and every one of them is unexercised because all test fixtures use the canonical header shape. Mutation survivors from the 18.08.2026 run, all confirmed green after mutation:

- The header window can shrink from 20 lines to 5 without failing. Consequence: a HANDOVER with YAML frontmatter or a longer preamble silently falls back to the 5 KB default instead of honouring its own declared cap. The upper side is pinned (widening to 2000 is caught); only the lower side is free.
- The trailing-newline line-count correction can be dropped without failing. A 150-line file with no trailing newline reports 149 and misses its cap by one line.
- re.IGNORECASE on the KB pattern can be dropped without failing. Only matters for a header writing "kb" or "Kb"; the shipped template writes "KB".
- The decode guard (errors="replace") can be removed so decoding raises. The test written for that input pins only "never blocks" -- the try/except swallows it and the exit code is 0 either way, so an undecodable HANDOVER would silently stop being size-checked while the test still passes.
- The over-cap boundary can move from >= 100 to > 100 without failing. A file landing exactly on 100 percent (5100-5145 bytes, reachable) is labelled "approaching" rather than "over"; both still warn, so only the label and the dedup slot change.
- round() can become int() on the percentage without failing. The two derivation fixtures sit at 80.06 and 79.00 percent, where the two agree, so the threshold pin is unaffected -- but the rounding itself is undefended.

Common cause, and the reason these belong in one item rather than six: the fixtures all use the canonical header, so every tolerance the parser was given on purpose is untested. The fix is a fixture set that departs from the canonical shape, not six isolated assertions.
