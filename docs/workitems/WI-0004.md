A tenant project name, an internal variant label and three story IDs sat in a shipped instinct's rationale while the file family's header claimed such details were anonymised. Found by hand, fixed in 8cd284e. memory-sync.sh gate already exists but is built for memory content: a sweep over all 205 tracked Markdown files produced 68 findings and ZERO true positives -- 60 content-type (Next Steps headings and checkboxes are legitimate skill-prompt structure), 5 personal (all triggered by 'red-green', the TDD cycle and red-green colour vision in a11y skills), 3 secret (Markdown table separators and a long snake_case test name). Decisive gap: the gate would NOT have caught the actual breach, because it has no concept of a tenant or project name. Three parts: (1) scope the reused checks, dropping content-type for shipped artifacts; (2) fix the 8 known false positives and keep them as regression cases; (3) add a configurable deny-list of tenant and project names, sourced from local config so the shipped script stays generic. Makes the Inviolable machine-enforced instead of discipline-enforced.
