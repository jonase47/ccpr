scripts/memory-sync.sh routes none of its output through a mask, while its sibling entry point artifact-gate.sh routes every emitted line through one (added in WI-0004). The same tool that now refuses a destination because it carries a configured tenant name will print that same class of name verbatim elsewhere.

Reproduced 19.08.2026: note "cloning $REPO_URL" and the status verb both print a deny-listed name verbatim when it appears in the shared repository URL. Also unmasked: note "promoted $dst -> $REPO_URL", echo "Running discipline gate on $src", "gate: file not found: $f", and $CONFIG in two notices -- the last contains $HOME and therefore a username.

The reasoning that kept this out of WI-0014 was "out of brief, and local-only". The first half held; the second no longer does. The new refusal message's own comment names the CI log as its audience, and this tool is invoked from CI in exactly the two-tier arrangement WI-0004 shipped. A terminal is a smaller audience than a CI log, but the rule should not have exceptions a reader has to remember.

Fix shape is known and already exists in the sibling: one masking emitter (say/warn/die) applied to the finished line, with config loading moved before argument parsing so the mask is populated when the first message can fire. artifact-gate.sh is the reference implementation; do not write a second one.

One deliberate exception carried over from that implementation: usage() prints the file's own header, which the sweep already covers, and masking it would corrupt the help text.
